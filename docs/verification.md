最终网络报告为 `artifacts/network-final/20261022-170924/result.json` 与 `20261022-171057/result.json`。全部客户端退出码为零，完整日志无引擎错误或泄漏。容量测试是本机真实 UDP 连接，尚不能证明公网弱网质量或手机端 32 机渲染性能。

混合设备报告为 `artifacts/android/mixed-20261022-173013/result.json`。Android 使用模拟器的 `10.0.2.2` 主机别名通过真实 ENet UDP 加入 PC 服务端；它与电脑客户端为不同进程。Android 宿主同时运行 31 个电脑客户端与虚拟机，记录到约 23–30 FPS，不能将该结果当作手机帧率。

Windows 独立包与 Android 构建/运行证据分别见 [Windows 验证](windows-verification.md)、[Android 验证](android-verification.md)。这些文件将明确区分编辑器、独立发行包、模拟器与真实手机。

单独的真实渲染压力入口为 `-- --arena-render-test --arena-duration=180`，也可直接打开 `res://scenes/arena/RenderCheck.tscn`。它驱动 32 个本地模拟机体，覆盖持续射击、四区循环、死亡重生和镜头切换，每五秒输出 `ARENA_RENDER_METRICS`；`--arena-metrics=user://render-check.jsonl` 可保存指标。正常完成须有 `ARENA_RENDER_OK` 和零退出码。此入口拒绝 headless 环境，不作为网络容量证据；网络容量仍由独立 ENet 客户端验证。当前原生渲染崩溃排查尚未完成，不能将短时压力通过视为稳定性结论。

`python tools/arena_render_check.py` 从默认 Main 场景启动三轮各 240 秒的实际 GPU 检查，每轮保存独立日志、JSONL 指标、四区 PNG 和 `result.json`。工具关闭自动渲染循环，逐帧主动绘制并交换缓冲，记录完成绘制帧数、像素哈希及实际 .NET 版本，避免窗口被遮挡后只继续模拟而误判通过。`--executable builds/windows/AirwarTogether.exe` 可改验包含新版检查入口的独立包；旧包缺少像素证据会判失败。任意引擎错误、原生崩溃、非零退出码、超时或缺少完成标志都会判失败；完整时长还要求四区都实际绘制并保存截图，像素持续变化。`--runs 1 --seconds 10` 仅用于入口自检，不能代表稳定性通过。续查和失败对照见 [原生渲染排查](native-render-investigation.md)。
